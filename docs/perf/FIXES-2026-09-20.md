The harness gained the "while something else runs" scenarios (`path.*.during_*`) so the
mutex invariant is a number from now on: `session.list` and a scrollback tail issued five
milliseconds into another op.

## What changed, file by file

- `handlers/overlap.rs` — `overlap.flag` and `overlap.scan` are `register_staged`: the status
  and tree-sitter pass runs in the unlocked read phase, and only crossing the result with the
  claims and writing rows holds the transaction. The claim's own overlap row is still computed
  from a fresh scan, so the result is what it was.
- `handlers/task.rs` — every statement `row_task` runs per task, `child_ids`, `depth_of`, the
  rollup walk, the label list and the built `task.list` statement use `prepare_cached`. The
  store's statement cache holds 128, so a dozen list shapes and seven per-row statements all
  stay compiled.
- `handlers/git.rs` — `branches_for` collects the tips, walks the base's ancestry once
  (stopping when the last tip is seen), and marks merged by set membership; the repository
  gets a 16 MiB object cache so `upstream_metrics` stops re-inflating commits too.
- `handlers/device.rs` — `resolve_run_root` checks membership with `worktree::contains`
  instead of listing worktrees with a dirty check.
- `worktree.rs` — `contains` reads the candidate's `.git` pointer and the repository's common
  dir from the filesystem; gix is opened only when `.git` is neither a directory nor a pointer.
- `recovery.rs` — `run_with(engine, DirtyScan::Deferred)` stores the report and fills
  `dirty_worktrees` in from a niced worker; `run` keeps the inline behaviour for tests.
  `serve::start` uses the deferred form.
- `handlers/file.rs` — `file.search` searches each file's text once and maps hits back to
  lines, one hit per line as before.

## Not done, and why

- **`file.tree` badges and `git.status` still run a `git status --porcelain` subprocess** on
  every call (about 10 ms for 1 500 files). Memoizing it needs the watcher's event stream as
  the invalidation signal, which is a change to `watch.rs` I did not want to make blind;
  it is the next item, and the number to beat is in the table.
- **`session.spawn` still renders the brief and materializes skills every time** (§1.8): a few
  milliseconds on a path that runs once per session.
- **`overlap`'s status still content-hashes every file** of a freshly created checkout: the
  fixture's index is written in the same second as the files (a "racy" index), so gix cannot
  trust stat data and hashes everything. On a checkout that is more than a second old only
  files whose stat changed are hashed, which is the work. Refreshing the index once after
  `git worktree add` would remove even the first-scan cost.
- **`pty::relay_children` still reads every process's environment** at startup (§1.5); at
  ~3 ms it is no longer on the critical path once the dirty walk moved.
- **`sessions::row` still reads columns by name**; 11 % of `session.list`, which is 39 µs.
