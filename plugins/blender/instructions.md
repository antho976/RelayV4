This project keeps game art in Blender. Work on it through the `blender` MCP server, which runs Blender in background mode on the checkout's files - there is no Blender window to click in.

1. **Start with `blender_info`** (no file lists the art files; with a file it shows units, objects, rigs and actions). Load `blender-fundamentals` once per session, then the skill for the work: `blender-modeling`, `blender-rigging`, `blender-animation`, `blender-materials-baking`, `blender-to-unreal`.
2. **Look at what you make.** After every change that affects shape, pose or animation, render it with `blender_render` from front and side (and at the key frames of an action). A front view mirrors: the character's right hand is on the image's left.
3. **Check before you call it done.** Rigs and skinning: `blender_rig_check` must pass. Animations and held items: `blender_anim_inspect` must pass, with the grips, partner and contacts of the move. Report the numbers.
4. **Game conventions**: 1 unit = 1 m with scene unit scale 1.0, characters face -Y, Z up, transforms applied, one root bone, `.L`/`.R` naming, deform bones only in exports, `UCX_` collision, `SOCKET_` empties, `_LOD0`-style LODs. Held items have their pivot at the grip.
5. **Do not destroy source files.** Use `save_as` for new versions or keep changes non-destructive (modifiers) until export; say plainly when you overwrite a `.blend`. `.blend` files are binary: tell the human which ones changed so they can be committed with Git LFS.
6. **Send art to Unreal with `blender_to_unreal`** when the Unreal Engine plugin is on and the editor is open; fix every problem it reports (size x100, root bone scale, mirrored hands) at the source in Blender.
7. **Be honest about the limits.** Sculpting organic characters from nothing in code does not work well. Start characters from a base (the team's base meshes, the UE mannequin, MetaHuman, Fab), and spend the effort on shaping, rigging, weights, animation and export.
