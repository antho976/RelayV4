This project is an Unreal Engine game. Work as an Unreal developer, through the tools this plugin installed:

1. **Start every task with `ue_project_info`** (the `unreal` MCP server) to learn the project name, engine version, modules and enabled plugins. Do not guess the engine version or module names.
2. **Load the matching skill before the work it covers.** Always load `unreal-fundamentals` once per session before your first change; then the domain skill — `unreal-cpp`, `unreal-blueprints`, `unreal-gameplay-framework`, `unreal-game-design`, `unreal-level-environment`, `unreal-narrative`, `unreal-ui-umg`, `unreal-animation`, `unreal-ai`, `unreal-gas`, `unreal-multiplayer`, `unreal-materials-vfx`, `unreal-audio`, `unreal-animation-verification`, `unreal-editor-automation`, `unreal-performance`, `unreal-build-packaging`, `unreal-testing-debugging`, `unreal-source-control`. More than one often applies.
3. **Never edit `.uasset` or `.umap` files as text**, and never delete `Binaries/`, `Intermediate/`, `Saved/` or `DerivedDataCache/` unless asked. Binary assets change only through the editor: `ue_python` (wrap mutations in `unreal.ScopedEditorTransaction`, save explicitly) or precise click-by-click steps for the human.
4. **Prefer text-first, diffable changes**: C++, `.Build.cs`/`.Target.cs`, `Config/*.ini`, `.uproject`, Python editor scripts, data as CSV/JSON imported into Data Tables.
5. **Verify every C++ change**: `ue_build` with `restart_editor: true` quits the editor, builds and relaunches it (there is no Live Coding on Linux; on Windows the human can press Ctrl+Alt+F11 instead), then `ue_log` with `Error|Warning`. Never report a C++ change as working without a successful build, and read `warnings` (hot-reload modules mean old code is running).
6. **Before editor work**, run `ue_editor_status`: it must be reachable *and* report `same_project: true`. If the editor is unreachable, run `ue_setup_check` and tell the human exactly what to enable instead of retrying blindly. If it has a different copy of the project open, live tools refuse: tell the human, and meanwhile do offline work.
7. **One agent drives the editor at a time.** Live tools that change the editor take a lock automatically; if another agent holds it, do offline work and try later. Run `ue_editor_lock` with `action: release` when your editor work is done.
8. **Binary assets cannot be merged.** Do not touch a map or asset another agent or person is editing; say which assets you changed in your summary so they can be committed (Git LFS) deliberately.
9. **Design as well as code.** For gameplay, levels, story, UI and feel, apply the design skills: state the player-facing goal first, keep values data-driven (Data Assets, Data Tables, Curve Tables, Gameplay Tags), and leave the game playable after every step.
10. **Prove runtime behaviour.** Gameplay changes are checked with `ue_play` (screenshots, a Python probe of the game world, and the log while playing) and with `ue_run_tests` where tests exist; performance claims come with `ue_profile` numbers.
11. **Stop on suspected engine bugs.** After two focused attempts on a problem that looks like an engine bug (reproduces in an empty level, call stack entirely in engine code, specific to one engine version), stop and hand it to the human with repro steps, version, log and call stack.
12. **Animation, rigging, attachments and character interactions are verified, never assumed.** Load `unreal-animation-verification`; measure with `ue_anim_inspect` and look with `ue_anim_preview` before and after every change, and report the numbers. Left and right mean the character's left and right. Anything you could not verify is reported as unverified.
13. **Track your work on the board.** If `session.bootstrap` gives you no task, create one for what you were asked to do (`task.create`), move it as you go (`task.move`), link your commits (`task.link_commit`) and finish with `session.done`.
14. **Commit working states before large rewrites.** Relay's guardrail holds a write that removes a lot of lines from a file with uncommitted changes, because nothing could bring those changes back; a committed file can be rewritten freely. Commit, then rewrite.
