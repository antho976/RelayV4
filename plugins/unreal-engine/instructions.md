This project is an Unreal Engine game. Work as an Unreal developer, through the tools this plugin installed:

1. **Start every task with `ue_project_info`** (the `unreal` MCP server) to learn the project name, engine version, modules and enabled plugins. Do not guess the engine version or module names.
2. **Load the matching skill before the work it covers.** Always load `unreal-fundamentals` once per session before your first change; then the domain skill — `unreal-cpp`, `unreal-blueprints`, `unreal-gameplay-framework`, `unreal-game-design`, `unreal-level-environment`, `unreal-narrative`, `unreal-ui-umg`, `unreal-animation`, `unreal-ai`, `unreal-gas`, `unreal-multiplayer`, `unreal-materials-vfx`, `unreal-audio`, `unreal-editor-automation`, `unreal-performance`, `unreal-build-packaging`, `unreal-testing-debugging`, `unreal-source-control`. More than one often applies.
3. **Never edit `.uasset` or `.umap` files as text**, and never delete `Binaries/`, `Intermediate/`, `Saved/` or `DerivedDataCache/` unless asked. Binary assets change only through the editor: `ue_python` (wrap mutations in `unreal.ScopedEditorTransaction`, save explicitly) or precise click-by-click steps for the human.
4. **Prefer text-first, diffable changes**: C++, `.Build.cs`/`.Target.cs`, `Config/*.ini`, `.uproject`, Python editor scripts, data as CSV/JSON imported into Data Tables.
5. **Verify every C++ change**: `ue_build` (with the editor closed, or ask the human to press Live Coding with Ctrl+Alt+F11), then `ue_log` with `Error|Warning`. Never report a C++ change as working without a successful build.
6. **Before editor work**, run `ue_editor_status`; if the editor is unreachable, run `ue_setup_check` and tell the human exactly what to enable instead of retrying blindly.
7. **Binary assets cannot be merged.** Do not touch a map or asset another agent or person is editing; say which assets you changed in your summary so they can be committed (Git LFS) deliberately.
8. **Design as well as code.** For gameplay, levels, story, UI and feel, apply the design skills: state the player-facing goal first, keep values data-driven (Data Assets, Data Tables, Curve Tables, Gameplay Tags), and leave the game playable after every step.
